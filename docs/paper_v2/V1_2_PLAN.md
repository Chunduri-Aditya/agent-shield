## Pilot rules (binding for every paid run; Aditya's text from the 2026-10-13 pilot prompt)
- R1 Spend cap: $25 total. $20 spendable, $5 reserve never touched. Spend is computed only by `scripts/pilot/cost.py` from token usage in `.eval` logs priced with `pilot/prices.yaml`, recorded in `$DATA/ledger.jsonl`. Console billing is a backstop, not the meter.
- R2 Fail closed: a failed gate, any HTTP 4xx, or missing evidence means stop. Write `$OUT/BLOCKED.md` with the cause, the evidence path, and the one decision needed, then end the session. Never change parameters and rerun.
- R3 Never edit scorer files. Their hashes are checked before and after every run.
- R4 Never pass temperature, top_p, top_k, seed, or `--fallback-models`. Never use `--batch`.
- R5 Canary payloads only. Never write or alter attack text, markers, tool descriptions, or directives.
- R6 Runs happen only from this worktree at the setup sha with `git status --porcelain` empty. Logs live in `$DATA`.
- R7 No published numbers. Never compute or print ASR, TR, or UUA from the current scorers. Their outputs stay inside the logs for rescoring with scorer v3.
- R8 Verify before claiming. Every statement in a report cites the script output or log path that shows it. A subagent finding counts only after a script confirms it.
- R9 Never ask me a question mid run. A needed decision is an R2 stop.
- R10 Anything that spends money is done by you, serially. Subagents are read only.

Where v1.2 departs from a rule, the step says so: D09 relaxes R7 for `tools_event_v1` (an event count, not a scorer rate); R4 was written for Claude API runs, and the local Llama rows of step 5 pin temperature 0 and seed 0 by the repo rule (judgment call J1).
